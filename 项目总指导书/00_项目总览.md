# Autonomous Vehicle Control Benchmark — 项目总览

## AI 上下文（每次将文件提供给 AI 时请先阅读本节）

**开发者背景：** 本科生，以学习自动驾驶控制算法为目的。C++ 和 Python 均为学过语法、未写过完整项目阶段。

**项目目标：** 在 CARLA 仿真器中实现并对比 PID、Pure Pursuit、Stanley、LQR、MPC 五种控制算法，使用 ROS2 作为通信层，控制器核心用 C++ 实现，Python 负责 CARLA 桥接与数据可视化。最终产出发布到 GitHub 的专业项目。

**技术栈：** CARLA 0.9.15 · ROS2 Humble · C++17 · Python 3.10 · Eigen3 · OSQP · CMake · Ubuntu 22.04 (WSL2) · RTX 4060 (8GB)

**开发环境：双机 SSH 方案**
- **开发电脑（主机）**：VS Code 写代码、Claude AI 辅助编程、Git 管理
- **第二台电脑（Windows 11）**：WSL2 Ubuntu 22.04，负责编译 C++、运行 Python 仿真、运行 ROS2
- **连接方式**：VS Code Remote-SSH 从开发电脑连接第二台电脑的 WSL2，代码在第二台电脑上运行

**辅助编程原则：**
- 代码注释用中文
- C++ 遵循 Google Style
- 优先解释原理再给代码
- 避免过度封装，项目以学习为主

## 项目定位

本项目参考工业界（Apollo、Autoware）控制模块的工程架构，具体实现：

### 三层迭代逻辑

```
第一层（第1-22周）：运动学模型 + Python/C++ 仿真
  ↓ 模型升级（引入轮胎侧偏力 + 横摆动力学）
第二层（第23-26周）：动态自行车模型
  ↓ 仿真器升级（替换为真实物理引擎）
第三层（第27-32周）：CARLA 物理引擎 + ROS2 全集成
```

**核心逻辑：仿真精度递增 → 控制器差距随之扩大 → 结论更具说服力。**

| 层次 | 仿真器 | 车辆模型 | 模型局限 | 结果用途 | MPC vs PP 差距 |
|------|--------|----------|----------|----------|----------------|
| 第一层 | Python 运动学模型 | 轮胎不打滑，忽略惯量 | > 8 m/s 假设失效 | 验证算法逻辑正确 | **实测 ~6%** ✅ |
| 第二层 | C++ 动态模型 | 含轮胎侧偏力 + 横摆惯量 | 参数理想，无噪声 | 体现控制器真实差距 | **实测 39%（15 m/s）** ✅ |
| 第三层 | CARLA 物理引擎 | Unreal PhysX，含传感器噪声和执行延迟 | 最接近真实 | 最终验证，最具说服力 | 待测（预计最显著） |

**为什么要分三层而不是直接上 CARLA？**

- 运动学模型计算最快，调试控制器逻辑时不需要启动仿真器，迭代速度快 10 倍以上
- 动态模型在 Python 内闭环运行，可以快速扫参（速度、控制器增益），帮助确认 MPC 的约束设计
- CARLA 有真实物理但启动慢、依赖 GPU，适合做最终验证而非日常开发

**为什么运动学模型下 MPC 优势不明显？**

运动学模型假设轮胎不打滑（速度 v 和车头方向始终一致），在 < 8 m/s 时成立。此时 PP/LQR/MPC 的预测误差都很小，控制器之间差距体现不出来。进入动态模型后，高速时轮胎侧偏角（β ≠ 0）显著，MPC 能通过预测未来 N 步的横摆动态提前补偿，而 PP/Stanley 只看当前时刻，差距因此拉大。

**与工业界的对应关系：**

> 这个三层框架和 Momenta、文远知行内部的"纯软件仿真 → 半实物仿真 → 实车"验证流程在逻辑上是一致的——先在最简单的环境里跑通算法，再逐步增加仿真精度，最终上实车验证。

## 双机 SSH 开发工作流

```
开发电脑（主机）
  │
  │  VS Code Remote-SSH（写代码，文件实际在第二台电脑上）
  │  Claude AI 辅助编程
  ▼
第二台电脑 WSL2 Ubuntu 22.04（编译 C++ · 运行 Python 仿真 · 运行 ROS2）
  │
  │  git push 到 GitHub
  ▼
GitHub 仓库（备份 + 对外展示）
```

**实际操作习惯：**
- 当前电脑安装 VS Code + Remote-SSH 插件，连接第二台电脑的 WSL2
- 所有编译、运行、git 操作在第二台电脑的 WSL2 终端里完成
- 仿真结果（PNG）保存在第二台电脑，通过 git push 同步到 GitHub 后在当前电脑查看
