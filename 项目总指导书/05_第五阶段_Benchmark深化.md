## 第十九周：修复 Stanley + 补充指标

### 19.1 修复 Stanley 高速发散

**问题根因：** Stanley 的 `compute()` 没有 `min_idx` 前向跟踪，每步全局搜索最近点，高速时会跳回已走过的轨迹段，导致振荡发散。

**修复方法：** 在 `stanley_controller.hpp` 增加 `lastNearestIdx()`，在 `compute()` 中加入起始搜索索引参数，和 Pure Pursuit 保持一致。

```cpp
// stanley_controller.hpp 修改
std::pair<double, double> compute(
    const Eigen::Vector4d& state,
    const std::vector<Waypoint>& trajectory,
    int min_idx = 0);   // 新增参数

int lastNearestIdx() const { return last_nearest_idx_; }

private:
    int last_nearest_idx_ = 0;   // 新增成员
```

修复后验证：双移线 8 m/s 下 Stanley RMSE 应降至 0.10m 以下。

---

### 19.2 补充评估指标

在 `cpp_controllers/scripts/plot_benchmark.py` 中增加以下指标：

| 指标 | 含义 | 计算方式 |
|------|------|----------|
| 最大横向误差 | 误差峰值 | `max(lateral_errors)` |
| 转向平顺度 | 转角标准差，越小越平顺 | `std(delta_series)` |
| 计算耗时 | 每步控制计算时间 | C++ chrono 计时，单位 μs |

**计算耗时说明：**
- Pure Pursuit / Stanley：< 1 μs（几何运算）
- LQR：< 50 μs（矩阵迭代，固定次数）
- MPC：100~500 μs（OSQP 求解，依赖问题规模）

耗时数据体现控制器的**实时性**，是工程项目中必须展示的维度。

## 第二十周：速度-RMSE 扫描（核心新图）

### 20.1 为什么这张图最重要

当前 Benchmark 只在固定速度下测试，无法展示控制器性能随速度的变化趋势。

速度-RMSE 曲线能直接说明：
- **低速段（< 6 m/s）：** 几何法（PP/Stanley）已足够
- **中速段（8-12 m/s）：** 优化类控制器（LQR/MPC）优势开始显现
- **高速段（> 12 m/s）：** 运动学模型失效，LQR/MPC 差距扩大，为动态模型（第六阶段）埋下伏笔

### 20.2 实现方案

修改 `cpp_controllers/src/main.cpp`，在双移线测试中循环速度参数：

```
测试速度：4, 6, 8, 10, 12, 14 m/s
测试场景：ISO 3888 双移线（不变）
控制器：Pure Pursuit / Stanley / LQR / MPC
输出：speed_sweep_results.csv
```

**预期曲线形状：**
```
RMSE
↑
|      PP ─────────────────────────/
|      Stanley ──────────────────/
|      LQR ──────────────────────
|      MPC ──────────────────────
|___________________________________→ 速度 (m/s)
   4    6    8   10   12   14
```

差距越大，说明优化类控制器的价值越明显。
